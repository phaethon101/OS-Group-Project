## 1. 写提示词前必须搞清楚的七件事

不搞清楚这些，写出来的提示词要么是"极简指令类"，要么会把错误当规格交出去。

### 1.1 这个模块只有三个分支，但有一个是陷阱

`page_insert` 看似"改一个页表项"，实际上必须区分三种情况：

| # | 情况 | 引用计数怎么变 | 容易错在哪 |
|---|---|---|---|
| ① | 该地址本来没有映射 | 新页 `+1` | 忘记 `page_ref_inc` |
| ② | 该地址已映射到**别的页** | 新页 `+1`，旧页 `-1`（为 0 则回收） | 忘了撤销旧映射 → 旧页泄漏 |
| ③ | 该地址已映射到**同一页** | **净变化 0** | **走了"先删后建"→ 把页释放掉** |

第 ③ 种就是本模块唯一的真陷阱。它的危害不只是计数错，而是**这一页此刻已经回到空闲链表，却仍然被页表引用着**——一个悬空映射。

### 1.2 引用计数是唯一的回收判据

```c
if (page_ref_dec(page) == 0) {
    free_page(page);
}
```

只有 `ref` 减到 0 才能还给 `pmm_manager`。这带来一个反直觉的后果：**`page_insert` 里必须先加引用，再判断要不要减**，否则在"同页"场景下无法既保住原有引用、又完成新映射。

标准写法：

```c
page_ref_inc(page);                  // 先无条件加
if (*ptep & PTE_V) {
    struct Page *p = pte2page(*ptep);
    if (p == page) page_ref_dec(page);      // 同页：退回去，净变化 0
    else          page_remove_pte(...);     // 不同页：撤销旧的
}
*ptep = pte_create(...);
```

### 1.3 TLB 必须失效——而这件事**测试测不出来**

任何一次页表项写入之后都要 `sfence.vma`：

```c
tlb_invalidate(pgdir, la);    // asm volatile("sfence.vma %0" : : "r"(la))
```

但这里有个坑值得单独强调：`tools/test_lab4.c` 只在 `0` / `PGSIZE` / `2*PGSIZE` 上**建立映射**，**从不访问这三个虚拟地址**。既然没有访问过，TLB 里就没有这三个地址的旧条目，所以**漏掉 `tlb_invalidate` 大概率仍然能通过测试**。

也就是说：这条要求**无法靠"跑通测试"来验证**，只能靠规格强制。同理还有下面两条。

### 1.4 `create` 参数决定"能不能分配"

```c
pte_t *get_pte(pde_t *pgdir, uintptr_t la, bool create);
```

- `create = 1`：中间级页表页不存在就 `alloc_page()` 建出来；
- `create = 0`：只查，缺层级就返回 `NULL`。

所以：

| 函数 | 必须用 | 理由 |
|---|---|---|
| `page_insert` | `create = 1` | 建立映射本来就可能需要新页表 |
| `page_remove` | **`create = 0`** | 删除路径**不允许**为了删一条不存在的映射而白分配两级页表页 |

这一条同样**测试测不出来**：测试里四次 `page_remove` 的目标地址页表都已存在，用 `create=1` 也不会多分配。但如果删一个从未映射过的地址，就会漏页。

### 1.5 `get_pte` 可能失败，失败时不留残局

`get_pte(pgdir, la, 1)` 内部会 `alloc_page()`，可能返回 `NULL`。此时必须：

```c
if (ptep == NULL) return -E_NO_MEM;    // 不写页表、不动 ref
```

好消息是这个失败路径**测试测不出来**（128 MiB 内存充足，`alloc_page` 不会失败）——所以它也是"只能靠规格强制"的一条。

### 1.6 `pte_create` 内部已经或上了 `PTE_V`

```c
static inline pte_t pte_create(uintptr_t ppn, int type) {
    return (ppn << PTE_PPN_SHIFT) | PTE_V | type;   // ← 注意这个 PTE_V
}
```

所以写页表项时传 `perm` 就行，不需要（也不该）写成 `pte_create(ppn, PTE_V | perm)`。传了不会错，但容易让人以为 `PTE_V` 是调用方职责。

### 1.7 验收标准是现成的，而且有两层

**第一层**：`tools/test_lab4.c::test_lab4_pmm_basic()`，输出 `[Test PMM] PASS`（10 分）。

**第二层**（更严格）：`pmm_init()` 里会调 `check_pgdir()` 和 `check_boot_pgdir()`，它们额外检查 `nr_free_pages()` 的收支：

```c
assert(nr_free_store == nr_free_pages());   // 全过程中不许泄漏、不许白分配
```

把它们的关键断言直接抄进提示词的后置条件，提示词就天然可验证了。

## 3. 第 1 轮：V1 · 极简指令类（故意做错，用于对比）

### 3.1 提示词原文

```text
帮我实现 lab4 的 page_insert 和 page_remove。
```

### 3.2 这一轮想验证什么

验证**"信息不足时 AI 一定按教科书套路填空"**。这句话没有错字，但它把七个关键决策全留给了 AI 猜：三个分支怎么分、引用计数怎么变、TLB 要不要 flush、`create` 传什么、失败怎么返回、`pte_create` 要不要补 `PTE_V`、返回值类型是什么。

### 3.3 典型产出与症状判定

AI 几乎一定会写出这种"非常符合直觉"的代码：

```c
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm) {
    pte_t *ptep = get_pte(pgdir, la, 1);
    if (*ptep & PTE_V) {
        page_remove(pgdir, la);              // ← 错 1：无条件先删
    }
    page_ref_inc(page);                      // ← 错 2：位置/顺序配合错
    *ptep = pte_create(page2ppn(page), perm);
    return 0;                                // ← 错 3：没有 TLB 失效
}

void page_remove(pde_t *pgdir, uintptr_t la) {
    pte_t *ptep = get_pte(pgdir, la, 1);     // ← 错 4：create=1
    struct Page *page = pte2page(*ptep);     // ← 错 5：没判 PTE_V，会 panic
    if (page_ref_dec(page) == 0) free_page(page);
    *ptep = 0;
}
```

| # | 症状 | 根因 | 现场表现 |
|---|---|---|---|
| 1 | 同页重复映射时把页释放了 | 不知道有"同一页"这个分支 | `assert(page_ref(p3) == 1 && nr_free_pages() == free_before)` 失败 |
| 2 | 首次映射后 `ref` 不是 1 | 只在"无映射"分支加引用，或顺序错导致抵消 | `assert(page_ref(p1) == 1)` 失败 |
| 3 | 没有 `tlb_invalidate` | 以为改了页表 CPU 自然看到 | **测试仍然通过**（测试不访问这些地址），但语义错 |
| 4 | `page_remove` 用 `create=1` | 以为"都要操作页表项" | 删除未映射地址时白分配两级页表页，`nr_free` 收支不平 |
| 5 | 对无效项调 `pte2page` | 不知道 `pte2page` 里有 `panic` | 第二次 `page_remove` 直接 `kernel panic: pte2page called with invalid pte` |
| 6 | 不检查 `get_pte` 返回 NULL | 假设分配一定成功 | 内存紧张时空指针解引用 |

**判定**：能过一部分断言，但第 1 条一定挂；第 2～6 条中至少两条会挂。

### 3.4 迭代决策 → V2

V1 的问题是"AI 在猜"。此时最容易犯的第二个错是：既然它猜不准，我就一步步教它——于是走向 V2 伪代码类。

## 4. 第 2 轮：V2 · 伪代码类（第二个反例，最危险的一轮）

### 4.1 提示词原文

```text
你按我说的写，不要自己发挥：
1. page_insert 里先调 get_pte(pgdir, la, 1)
2. 如果这个 pte 有效，先调用 page_remove 把旧映射删掉
3. 然后 page_ref_inc(page)
4. 再 *ptep = pte_create(page2ppn(page), perm)
5. page_remove 里调 get_pte(pgdir, la, 1)，然后把 pte2page 的 ref 减一
6. 如果 ref 变成 0 就 free_page
7. 最后把页表项清 0
```

### 4.2 这一轮想验证什么

验证一个反直觉的结论：**伪代码式提示词比极简指令更危险。**

因为极简指令下，错误是"AI 猜的"，你还能怀疑它；而伪代码式下，错误是"**我要求的**"。第 2 条和第 5 条恰好把 V1 里的错 1 和错 4 变成了硬性规格——AI 会忠实执行并告诉你"已完成"。

### 4.3 典型症状判定

| 症状 | 说明 |
|---|---|
| 代码"完全符合要求"但测试依然挂 | 因为规格本身就错 |
| AI 去 `tools/test_lab4.c` 注释掉失败断言 | 伪代码没划"不许改"的边界，AI 的优化目标漂移成"让测试不报错" |
| AI 把 `page_ref_inc` 删掉了 | "先删再加"会互相抵消，AI 选择让代码自洽，而不是指出规格互相矛盾 |
| 追问"为什么同页也要删"，AI 答不上来 | 它手里只有你的步骤，没有"引用计数不变式"这个模型 |

**判定**：这一轮最有价值——它证明**约束应当由"行为规格"表达，而不是由"操作步骤"表达**。要描述"函数返回时计数必须等于多少"，让 AI 自己找路径，它才有机会纠正你的错误。

### 4.4 迭代决策 → V3

该描述结果了。但只描述结果还不够——还得划"哪些能改、哪些不能改"，否则 AI 会用改测试来绕过你的规格。

## 5. 第 3 轮：V3 · 任务导向但边界不清

### 5.1 提示词原文

```text
在 kern/mm/pmm.c 里实现 page_insert() 和 page_remove()，完成虚拟内存映射的建立和撤销。
注意处理好引用计数和 TLB，不要改坏别的东西。
```

### 5.2 这一轮想验证什么

这条已经比 V1/V2 好：**任务导向**做到了（一个完整功能模块）、**保留工程语义**也提到了。但两个坑仍在：

- **边界不清**："别的东西"指什么？`check_pgdir()` 能改吗？`test_lab4.c` 呢？`pmm.h` 里的 `static inline` 呢？
- **要求不可验证**："注意处理好引用计数"是一句形容词，无法翻译成"哪几个分支、每个分支计数怎么变"。

### 5.3 典型症状判定

| 症状 | 根因 |
|---|---|
| 漏掉"同一页"分支 | "注意引用计数"没有指向具体分支清单 |
| 漏 `-E_NO_MEM` | 测试环境内存充足，AI 认为"不会失败" |
| `page_remove` 第二次调用 `panic` | 没说"必须幂等"，AI 没判 `PTE_V` |
| 函数签名被改成 `void` | 没说"签名必须与 `pmm.h` 逐字一致" |
| 声称"已处理所有边界"但同页仍错 | 没有可执行的验收标准，AI 无法自查 |

**判定**：失败点非常清晰——**"模糊的正确"等于"不可验证"**。必须把每条要求换成能一条条对账的断言。

### 5.4 迭代决策 → V4

补三样东西：

1. 把任务拆成 Prompt（任务+约束+输出验证要求）/ Rely（最小依赖集+框架事实）/ Guarantee（接口清单+不可改清单）/ Specification（逐分支行为+后置断言）；
2. 把"注意引用计数"换成 **S3a / S3b 两个编号分支 + "净变化为 0"这类可计算等式**；
3. 把"不要改坏别的东西"换成一份**逐项列出的不可修改清单**，特别点名 `check_pgdir()` 和 `tools/test_lab4.c`。

## 6. 第 4 轮：V4 · 四段式标准提示词（最终版，直接复制）

> 用 ```` 包裹是为了让你一键复制。

````text
# 任务：实现 riscv64-ucore lab4 的 page_insert() 与 page_remove()

## 【Prompt｜任务说明】

### 任务详情
在 riscv64-ucore 的 lab4 工程中，实现 `kern/mm/pmm.c` 里位于
`//LAB4 function1 YOUR CODE` 标记处的两个函数：
`int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm)`
与 `void page_remove(pde_t *pgdir, uintptr_t la)`，
补齐虚拟内存页表映射的建立与撤销能力，使 `check_pgdir()`、
`check_boot_pgdir()` 与 `tools/test_lab4.c::test_lab4_pmm_basic()` 全部通过。

### 操作约束
- 只允许修改 `kern/mm/pmm.c`，且改动范围仅限标记处：新增这两个函数、
  可选地新增 `static` 内部辅助函数、补齐必要的 `#include`。
- 必须原样保留 `//LAB4 function1 YOUR CODE` 这行注释。
- 两个函数的签名必须与 `kern/mm/pmm.h` 中的声明**逐字一致**。
- 代码风格与同文件一致（4 空格缩进、Allman 花括号风格）。
- 必须零警告编译通过（lab4 已移除 `-Werror`，但仍要求零警告）。
- 不要输出测试代码，不要输出 README，不要改 Makefile。

### 输出验证要求
- 给出可直接替换的完整代码块（两个函数 + 辅助函数）。
- 逐条说明你的实现如何满足下面【Specification】的后置条件 1~13。
- 如果认为某两条约束无法同时满足，先指出冲突再给方案，不要静默取舍。

## 【Rely｜依赖说明】

实现本功能只需要以下文件，不要引入其他材料（尤其不要把整本指导书贴进上下文）：

1. `kern/mm/pmm.c` —— 待改文件。重点看 `get_pte()`（第 177 行起）、`get_page()`、
   `tlb_invalidate()`，以及 `check_pgdir()` / `check_boot_pgdir()` 对这两个函数的用法。
2. `kern/mm/pmm.h` —— `page_insert` / `page_remove` 的声明，
   `page2ppn` / `pa2page` / `pte2page` / `pte_create` / `page_ref_inc` /
   `page_ref_dec` / `set_page_ref`，以及 `alloc_page` / `free_page` 宏。
3. `kern/mm/mmu.h` —— `PTE_V` / `PTE_R` / `PTE_W` / `PTE_X` / `PTE_U`、
   `PTE_ADDR` / `PDE_ADDR`、`PTX` / `PDX0` / `PDX1` / `PGOFF`、`PTE_PPN_SHIFT`。
4. `libs/error.h` —— `E_NO_MEM`。
5. `tools/test_lab4.c` —— `test_lab4_pmm_basic()` 的断言，作为验收依据。
6. `tools/grade.sh` —— 确认 Test PMM 的 sentinel 是 `[Test PMM] PASS`。

已替你确认的背景事实（不必再查）：
- `pte_create(ppn, type)` 的实现是 `(ppn << 10) | PTE_V | type`，
  **内部已经或上了 `PTE_V`**，调用时不需要再传。
- `get_pte(pgdir, la, create)` 在 `create=1` 时可能为建立中间级页表而调用
  `alloc_page()`；分配失败返回 `NULL`，且**不会留下半建成的层级**。
- `get_pte` 建表时对被用作页表的物理页执行 `set_page_ref(page, 1)`。

## 【Specification｜行为规格】

### 前置状态
- `pmm_init()` 已建好 `pages` 数组与 `boot_pgdir_va`（三级页表根）。
- `alloc_page()` 返回的 `struct Page *` 的 `ref == 0`。
- `get_pte(pgdir, la, 0)` 在页表层级缺失时返回 `NULL`。

### page_insert 的执行步骤
S1. `ptep = get_pte(pgdir, la, 1)`。若为 `NULL`，直接 `return -E_NO_MEM`；
    此时**不允许**写任何页表项，也不允许改动 `page->ref`。

S2. 无条件 `page_ref_inc(page)`。

S3. 若 `*ptep & PTE_V` 成立（该地址已有映射），按两种情况处理：
- **S3a 同一页**：`pte2page(*ptep) == page` → `page_ref_dec(page)`，净变化为 0。
  **绝对不要在这里调用 `page_remove` 或 `page_remove_pte`**。
- **S3b 不同页**：先把旧映射完整撤销（旧页 `ref` 减 1，减到 0 则 `free_page`，
  页表项清零，TLB 失效），然后再写新映射。

S4. `*ptep = pte_create(page2ppn(page), perm);`（`PTE_V` 由 `pte_create` 负责）

S5. `tlb_invalidate(pgdir, la);`

S6. `return 0;`

### page_remove 的执行步骤
T1. `ptep = get_pte(pgdir, la, 0)` —— **`create` 必须为 0**，删除路径不允许分配页表页。

T2. 若 `ptep == NULL`，直接返回。

T3. 若 `*ptep & PTE_V`，执行"撤销单条页表项"动作；否则什么都不做。
    **幂等**：连续调用两次与调用一次效果一致。

### 撤销单条页表项的动作（可抽成辅助函数）
U1. `page = pte2page(*ptep)`；
U2. 若 `page_ref_dec(page) == 0` 则 `free_page(page)`；
U3. `*ptep = 0`；
U4. `tlb_invalidate(pgdir, la)`。

### 后置条件（必须同时成立，全部可验证）
1. 两个函数签名与 `pmm.h` 声明逐字一致，`page_insert` 返回 `int`。
2. 对未映射地址首次 `page_insert` 成功后，`page_ref(page) == 1`。
3. 目标地址原本映射到**别的页**时：旧页 `ref` 减 1（减到 0 则回收），新页 `ref` 加 1。
4. 目标地址原本映射到**同一页**时：`page_ref(page)` 保持不变，
   且 `nr_free_pages()` 不变。
5. 对已映射地址 `page_remove` 后：该页 `ref` 减 1，页表项为 0。
6. 对未映射地址 `page_remove`：安静返回，`nr_free_pages()` 不变，不产生新的页表页。
7. 连续两次 `page_remove` 同一地址：第二次不改变任何计数，不 panic。
8. 每一次成功写入页表项之后都调用了 `tlb_invalidate(pgdir, la)`。
9. `get_pte` 返回 `NULL` 时返回 `-E_NO_MEM`，且页表与计数均未改动。
10. 写入后的页表项的 `PTE_V` 位为 1。
11. 写入后的页表项权限位**严格等于** `perm`（`perm == 0` 时 `PTE_U`、`PTE_W` 都为 0）。
12. `check_pgdir()` 结束时 `nr_free_pages()` 与进入时相等。
13. `test_lab4_pmm_basic()` 全部断言通过，输出 `[Test PMM] PASS`。
````

### 8.4 本模块与 OS 原理的对应关系（报告"知识点"那节要用）

| 实验里的东西 | OS 原理里的概念 | 关系与差异 |
|---|---|---|
| `page_insert` / `page_remove` | 页表维护接口 | 原理把页表当已存在对象，讲"MMU 怎么翻译"；实验要求你写"谁来维护这张表"。原理是使用者视角，实验是实现者视角 |
| `struct Page.ref` | 物理页共享 / COW 基础 | 原理以 COW 为例讲共享；实验里 `ref` 是能否回收的唯一判据，且"同页多地址映射"这种最朴素的共享形态必须自己处理 |
| `tlb_invalidate` / `sfence.vma` | TLB 一致性 | 原理一句话"改页表要刷 TLB"；实验给出具体指令，并暴露"QEMU 上不刷也可能看似正确"这一陷阱 |
| `get_pte(..., create)` | 多级页表按需建立 | 原理讲三级结构与查表路径；`create` 是惰性建立的开关，删除路径必须关掉——这个副作用原理不讲 |
| `-E_NO_MEM` + 不留半完成映射 | 分配失败与操作原子性 | 原理停在"分配可能失败"；实验要求失败路径可回滚，是"全有或全无"的工程约束 |
| `pte_create` / `PTE_PPN_SHIFT` | 页表项位布局 | 原理给位图；把位图写成代码时那一次 `<< 10` 和 `PTE_ADDR` 的 `<< 2` 补偿，原理图上看不到 |
| `boot_pgdir_va` / `boot_pgdir_pa` | `satp` 与页表基址 | 原理讲 `satp.PPN` 指向根页表物理页；实验里同一个页表有两个身份（CPU 旁路访问用 VA，写 `satp` 用 PA） |
| `PTE_U/W/X` 权限位 | 内存访问控制 | 原理讲权限实现保护；实验只把权限位写对并断言，**没有触发一次真实权限违例** |

### 8.5 原理上有、本实验没覆盖的点

- **写时复制（COW）**：`ref` 是 COW 基础，但 `copy_mm()` 本阶段是占位，不做 mm 复制与 COW 拆分。
- **缺页异常驱动按需分页**：只有"主动建映射"，没有"PTE 无效 → page fault → 现场分配"（`check_pgfault()` 在 lab4 被注释掉）。
- **大页映射（2 MiB / 1 GiB）**：只用 4 KiB 页，中间级页表项从未作为叶子使用。
- **ASID 与 TLB 分代**：`satp.ASID` 恒为 0，单地址空间，没有按 ASID 失效的需求。
- **多核 TLB shootdown**：单 hart，只需本地 `sfence.vma`。
- **空页表页回收**：`page_remove` 清叶子项后不检查中间级页表是否变空并回收。
- **映射变更的并发安全**：`page_insert` 未包 `local_intr_save`；真实系统需考虑中断与 SMP。
